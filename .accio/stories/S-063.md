## Context
After this ships: `/accio` goes from a new design note straight to sort, every flag that decides whether a review step runs comes from a script, and mad-eye can't quietly wander off the preview. We'd know because after the next wand note `accio-board next` says `sort`; `brew.js` asks portkey to compute no flag itself; a test shows an off-origin page after a click is hidden from mad-eye and fenced; auror's checklist has the two-parsers line; and the next story that adds an agent lists `accio/README.md` in its `files`.

Why this story: requirement L5 of "Group B leftovers", first half. The 0.7.1 push security review found that a mad-eye click can leave the preview, since curfew checks only `browser_navigate`.

Design: a PostToolUse hook on browser tools (matcher `mcp__.*__browser_.*`) acts only for `accio:mad-eye`. It finds the `- Page URL:` line in the tool's response and compares its origin with `preview.url`, using curfew's `policy._origin`. The `tool_response` is a list of content blocks; read the `text` of each `type: text` block (spike S-L5, `accio/docs/research/spike-s-l5.md`). A response with no `Page URL` line (`browser_close` has none) changes nothing. Off the origin, it returns `updatedMCPToolOutput` with the reason in place of the page, appends a line to the fence log, and writes a fence record for that `agent_id`. The fence lifts when a response shows the preview's origin again. The hook fails open (decision 007): a crash adds no output. Curfew's side is the next story.

Fence record (S-064 reads it, so both stories use exactly this): one JSON file `.accio/run/mad-eye-fence.json` holding a map `{"<agent_id>": {"url": "<off-origin Page URL>"}}`. Writing adds or replaces that agent's key; lifting removes it; other keys stay. Write it under `runlock.guard(run_dir)`, as curfew does for claims. Define the file name as `FENCE_NAME = "mad-eye-fence.json"` in `accio/bin/accio_lib/runlock.py` beside `CLAIMS_NAME`; S-064 imports it from there.

Story ID for the log: the hook reads the claims file in `.accio/run/` (`runlock.CLAIMS_NAME`, a map `agent_id -> {"story": ID, ...}`, as curfew's `_claims` does) and takes the story for the payload's `agent_id`. The log is `.accio/run/<ID>/mad-eye-fence.log`; with no claim for that agent it is `.accio/run/mad-eye-fence.log`.

Defaults (prophecy, iteration 20): `updatedMCPToolOutput` has the response's own shape, a list with one `{"type": "text", "text": "<reason>"}` block; the reason names the off-origin URL and says to `browser_navigate` back to the preview. A fence log line is `<UTC time, ISO 8601> <agent_id> <tool_name> <off-origin Page URL>`. When several text blocks hold a `Page URL` line, the first one counts.
## Reuse
`policy._origin` in `accio/bin/accio_lib/policy.py`; `runlock.guard` and `runlock.CLAIMS_NAME` in `accio/bin/accio_lib/runlock.py`; `_read_json`, `_write_json` and `_claims` in `accio/hooks/curfew.py`; the fixture `accio/tests/fixtures/browser-click-offorigin.json` from S-059; other hooks in `accio/hooks/` and their entries in `hooks.json`.
