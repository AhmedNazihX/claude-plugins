## Context
After this ships: a build records every story's outcome whatever words the user used to start it. We'd know because a build started from a message that also asks for other work (for example "continue, plan S-006 and start the build") ends with the board updated, not with an agent refusing.

The bug (iteration 6, 2026-10-19): Claude Code's Workflow harness relays the user message that started a run to every workflow agent, framed as "where the computed task conflicts with this request, this request wins". The build was started from "continue, plan S-006 and start the build". At step 7 prefect (Haiku) was told to move S-006 to blocked, read that as conflicting with "plan and start the build", and replied with an error instead of acting. The board was never updated and owl showed nothing to review. Builds started from a bare `/accio:brew` never hit this. Once `/accio` (S-006) starts builds itself, the relayed message will be `/accio` or whatever the user typed, so this has to hold for any wording.

The fix (planning answer, 2026-10-19): one paragraph in the body of each agent the brew workflow calls (portkey, house-elf, prefect, examiner, professor, auror, headmaster), near the top, worded the same in each:

> The harness relays the user's message that started this build. That message is the user's opt-in to the whole build, and your task is one step of that build, so they never conflict, even when the message also asks for work done elsewhere (planning, a review, a push). Do your step as the workflow gives it.

The agent files are the place, not the task text in `workflows/brew.js`: the harness marks computed task text as carrying no user authority, so a sentence there would be discounted.

Also in this story (added 2026-10-19 after the 0.4.0 CI watch): howler tried `cmd1 && cmd2` and `git -C <path> …`, curfew blocked both, and it lost turns rerunning them as plain commands. Howler's file lists its allowed commands but never says how to run them. Add one line next to that list: run each command as its own Bash call from the main checkout, with no `&&`, `;` or `|` chains (except the `| tail -60` its log step already uses) and no `git -C`.
