## Context
After this ships: the user types one command (`/accio`) and accio carries the work from wherever the board stands to a pushed, CI-checked result, stopping only at real decisions. We'd know because in one real iteration the transcript has a single `/accio`, every other message from the user answers a real question, and no step ends with "type /accio:X".

This story is the base: one copy of the "what's next" rule (design "One command: /accio", part 1, R4). Today it is written twice, in `accio/hooks/session_start.py` and `accio/skills/map/SKILL.md`. The `auto` values below are the starting set; S-008 later changes them for prophecy and owl.
## Reuse
`next_step()` in `accio/hooks/session_start.py` (move it, keep its sentences).
## Definition of Done
- [ ] S-005/1 WHEN `accio-board next --json` runs THE SYSTEM SHALL print the step (`wand`, `sort`, `prophecy`, `brew`, `owl`, `wait` or `done`), `auto` (true or false) and today's plain sentence
- [ ] S-005/2 WHEN the board is in each state THE SYSTEM SHALL return this step and auto: lock held gives `wait`, false; doing gives `brew`, true; review gives `owl`, false; blocked gives `owl`, false; ready gives `brew`, true; backlog gives `prophecy`, false; no design gives `wand`, false; no stories gives `sort`, true; all done gives `done`, false
- [ ] S-005/3 WHEN `session_start.py` builds its message THE SYSTEM SHALL use `nextstep.py` and not a copy of the rule
- [ ] S-005/4 WHEN the `map` skill is read THE SYSTEM SHALL tell the agent to run `accio-board next` and not hold the rule list (a test fails if the list is still in `map` or the hook)
