## Context
After this ships: a build stops for the user only for a real decision, and every finding, block and break leaves a reason. We'd know because over the next two iterations no story blocks with "Should it be fixed and built again?" or on a one-off accio hiccup; each `.accio/iterations/<N>.md` has one line per finding and block saying how it ended; every boggart break that reached a fix round came with a repro that failed twice on head; owl reports a cost for every build; and the guard and allow-list tests pass.

Why this story: R4 of "Group B: fewer stops, a reason for every ending". boggart tries to break each reviewed code story. prefect runs `accio-break <ID> verify`, so boggart never grades itself. A `code` flag next to `risky` in the review package tells the workflow whether the diff has code.
Before this story is built (iteration 14 review, 2026-10-20): S-042/5 was never run. Run boggart by hand on `accio/evals/boggart/` (steps in its README) after S-052 gives boggart its curfew list, and build this story only if at least 2 of the 3 planted breaks are caught and nothing is kept on the 3 clean stories. A boggart that keeps false breaks would start needless fix rounds here.
Eval result (2026-10-20, by hand, Claude Code 2.1.304, accio from main at `6a35540`, about $0.34 a case, $2.01 for six): boggart caught 3 of 3 planted breaks and kept nothing on the 3 clean stories, so the gate above is met for boggart itself. But `accio-break` kept only 1 of the 3: the other two fail on base with an import error (the story added the code) and were called pre-existing. S-055 fixes that; this story waits on it.
Settled at planning (iteration 17, user chose option A): since S-052, a kept repro that fails twice on head for any reason stays kept. When a fix round renames or moves code the repro imports, it fails to load (a setup error), not because the bug is back. So before such a repro counts, boggart gets one turn to update the repro's imports or setup (never its claim or expected value), and `verify` runs again: still failing is kept, passing is fixed, still unable to load is logged as "repro can't load" and starts no fix round.
## Reuse
The review step and fix-round code in `accio/workflows/brew.js`; `accio/bin/accio_lib/review.py` for the review package; owl's line writer from S-048.
## Definition of Done
- [ ] S-043/1 WHEN the review package is built THE SYSTEM SHALL include a `code` flag that is false for a diff with no code
- [ ] S-043/2 WHEN a story's diff has code and reviewers pass THE SYSTEM SHALL call boggart, then prefect to run `accio-break <ID> verify`
- [ ] S-043/3 WHEN `verify` keeps a break that touches a DoD line THE SYSTEM SHALL start a fix round with `boggart-findings.md`
- [ ] S-043/4 WHEN `verify` keeps a break outside the DoD THE SYSTEM SHALL pass the break to owl's line writer in `accio/bin/accio_lib/owl.py` (S-048/6), which adds it to `## Findings and blocks`, and start no fix round
- [ ] S-043/5 WHEN the diff is docs-only or `config.json` has no `breaker` command THE SYSTEM SHALL not call boggart and SHALL log the skip
- [ ] S-043/6 WHEN a kept in-DoD break remains after both fix rounds are spent THE SYSTEM SHALL block with its repro
- [ ] S-043/8 WHEN `verify` after a fix round keeps a break only because its repro fails to load (a setup error on head) THE SYSTEM SHALL call boggart once to update that repro's imports or setup, keeping its claim and source, and run `verify` again; WHEN it still fails to load THE SYSTEM SHALL log it as "repro can't load" through owl's line writer and start no fix round for it
- [ ] S-043/7 (no test) checks pass: `python3 tests/run_tests.py` and `node --test 'tests/workflow/**/*.test.mjs'`
