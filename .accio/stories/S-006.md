## Context
After this ships: the user types one command (`/accio`) and accio carries the work from wherever the board stands to a pushed, CI-checked result, stopping only at real decisions. We'd know because in one real iteration the transcript has a single `/accio`, every other message from the user answers a real question, and no step ends with "type /accio:X".

This story is the conductor (design "One command: /accio", part 3, decision 003). It runs `accio-board next --json`, runs that step's skill in the same chat, and repeats while `auto` is true. Python decides continue or stop; the skill only follows it. The by-hand spikes (part 2: S1 and the wake) are story S-014 and are done first. S-014 passed both (its Review notes, 2026-10-19): **the skill starts the build itself** (on step `brew` it loads `accio:brew` and calls `Workflow`; typing `/accio` is the user's opt-in, so it never says "type /accio:brew"), and **it picks up at review after the build** (the build's end notice wakes the chat; on that notice the skill reads `accio-board next` again and goes on to owl). On step `wait` (a build is running) it says so and carries on at the end notice.

What `auto` means (planning answer, 2026-10-19): `auto: false` does not stop `/accio` before the step; it means the step will need the user. The skill still runs that step's skill (wand, prophecy, owl), and the stop is that skill's own question to the user; after the answer it carries on and reads the board again. Only `done` stops with no skill: it reports the sentence and asks what to design next.
