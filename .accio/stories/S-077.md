## Context
After this ships: when sort reads a design note that leads to no new story, `run/unsorted.json` still empties, so
`accio-board next` moves on from `sort`; and `accio-preview <ID> evidence --head` only takes a full 40-character commit
id, so a short id of the right commit can't be refused as "old evidence".

Why: two boggart breaks kept on 2026-10-24 that never reached a fix round (curfew blocked their verify since 0.8.0;
see S-076) and still fail on main. 1) S-060/4: `accio-board record` requires at least one file
(`record.add_argument("files", nargs="+")`), and sort's step 5 passes "each story file in the list", so with no new
story nothing empties `unsorted.json` and `/accio` says `sort` forever until someone deletes it by hand. Repro:
`.accio/run/S-060/boggart/repros/record_empty_without_story.py`. 2) S-068/5: `accio-preview` accepts a 7-40 hex `--head`
but compares it to the full `git rev-parse HEAD` stamp as text. brew always passes the full id (from `accio-brief
--review`), so real builds aren't hit; only a model shortening the id when copying it would be. Repro:
`.accio/run/S-068/boggart/repros/test_short_head.py`.
## Definition of Done
- [ ] S-077/1 WHEN `accio-board record` runs with no story files THE SYSTEM SHALL empty `unsorted.json`, commit nothing else, and `next` SHALL no longer say `sort`
- [ ] S-077/2 WHEN sort's design note leads to no new story THE SYSTEM SHALL tell it (in `skills/sort/SKILL.md` step 5) to run `accio-board record` with no files
- [ ] S-077/3 WHEN `accio-preview <ID> evidence --head` gets anything but a full 40-character lowercase commit id THE SYSTEM SHALL refuse it with a clear error
- [ ] S-077/4 (no test) checks pass: `python3 tests/run_tests.py` and `node --test 'tests/workflow/**/*.test.mjs'`
