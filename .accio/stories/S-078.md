## Context
After this ships: a test's temp repo cleanup on a Linux runner never fails a passing test with "Directory not empty".

Why: CI run 40109367132 (2026-10-24, 0.11.1, Ubuntu) failed one test whose own assertions passed:
`test_owl.OwlTest.test_S_022_4_drop_...` errored in `tearDown` (`self.tmp.cleanup()`):
`OSError: [Errno 39] Directory not empty: '/tmp/.../app/.git'`. The rerun passed, macOS passed, and it passes 8/8 on
a laptop, so something (likely git writing into `.git` just after the test's last command) races the delete. A flaky
cleanup blocks releases: the release waits on green CI.

Design: one shared cleanup in `tests/support.py` that retries `shutil.rmtree` a few times with a short wait on
`ENOTEMPTY`/`EBUSY`, used by every test class that makes a temp repo (start with `test_owl.py`; grep for
`tmp.cleanup()`). Keep a real failure loud: after the retries, raise.
## Definition of Done
- [ ] S-078/1 WHEN removing a test's temp folder hits "Directory not empty" or "busy" THE SYSTEM SHALL retry a few times before failing
- [ ] S-078/2 WHEN the folder still can't be removed after the retries THE SYSTEM SHALL raise the error
- [ ] S-078/3 (no test) checks pass: `python3 tests/run_tests.py`
