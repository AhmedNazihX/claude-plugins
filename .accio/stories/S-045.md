## Context
After this ships: a build stops for the user only for a real decision, and every finding, block and break leaves a reason. We'd know because over the next two iterations no story blocks with "Should it be fixed and built again?" or on a one-off accio hiccup; each `.accio/iterations/<N>.md` has one line per finding and block saying how it ended; every boggart break that reached a fix round came with a repro that failed twice on head; owl reports a cost for every build; and the guard and allow-list tests pass.

Why this story: R8 and R9 of "Group B: fewer stops, a reason for every ending" (decision 008), first part. `accio-preview <ID> start` runs the user's `preview: {command, url}` in the story's worktree as a detached process; `stop` kills it. The next story (S-049) adds the test-data and login gates. portkey may run the script (policy.py).
## Reuse
The detached-process and lock handling used elsewhere in `accio/bin/accio_lib/`; config loader `config.py`.
## Definition of Done
- [ ] S-045/1 WHEN `accio-preview <ID> start` runs with a valid `preview` config THE SYSTEM SHALL start the command in the story's worktree, record its pid in `run/<ID>/preview.json`, and return once the URL answers
- [ ] S-045/2 WHEN a second `start` runs while a preview is up THE SYSTEM SHALL wait on `run/preview.lock`
- [ ] S-045/3 WHEN `stop` runs THE SYSTEM SHALL kill the process group, free the port and remove `preview.json` and `preview-login.json`
- [ ] S-045/4 WHEN `stop` runs after a crashed `start` THE SYSTEM SHALL still free the port
- [ ] S-045/5 (no test) checks pass: `python3 tests/run_tests.py`
