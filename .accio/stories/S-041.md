## Context
After this ships: a build stops for the user only for a real decision, and every finding, block and break leaves a reason. We'd know because over the next two iterations no story blocks with "Should it be fixed and built again?" or on a one-off accio hiccup; each `.accio/iterations/<N>.md` has one line per finding and block saying how it ended; every boggart break that reached a fix round came with a repro that failed twice on head; owl reports a cost for every build; and the guard and allow-list tests pass.

Why this story: R4 of "Group B: fewer stops, a reason for every ending". The script half of boggart. `accio-break <ID> try <file>` and `accio-break <ID> verify` copy each repro into a throwaway worktree at head (and base) and run a new config command `breaker: {"command": "... {file}"}`. It runs repro code, as checks do.

Defaults set at planning (iteration 13): each repro file starts with two comment lines, `claim: <quoted text>` and `source: <DoD id like S-012/3, or file:line>`; a missing or empty one means "no written claim" (S-041/7). The command's exit code 0 is a pass. A non-zero run is read from its output: a setup-error marker is `ImportError`, `ModuleNotFoundError`, `SyntaxError`, `IndentationError`, `fixture '…' not found` or `command not found`; an assertion is `AssertionError` (or the runner's own assert failure line); a crash in a changed file is a traceback line naming a file in `git diff --name-only <base> <head>`. Base is the review package's `origin` commit. `verify` prints JSON and writes `run/<ID>/boggart/verdicts.json`, one entry per repro with `file`, `verdict` (kept, dropped, pre-existing, fixed), `reason`, `claim`, `source` and `in_dod` (true when `source` is a DoD id of this story), so S-043 can tell in-DoD breaks from the rest.
## Reuse
The throwaway-worktree and command-run code in `accio/bin/accio_lib/checks.py`; the config loader in `config.py`.

- [ ] S-041/2 WHEN a repro crashes twice on head in a changed file THE SYSTEM SHALL keep it
- [ ] S-041/3 WHEN a repro fails with an import or other setup-error marker THE SYSTEM SHALL drop it
- [ ] S-041/4 WHEN a repro passes on head THE SYSTEM SHALL drop it
- [ ] S-041/5 WHEN a repro fails on head only 1 of 2 runs THE SYSTEM SHALL drop it
- [ ] S-041/6 WHEN a repro fails on base too THE SYSTEM SHALL mark it pre-existing and out of scope
- [ ] S-041/7 WHEN a kept repro has no written claim quoted with its source THE SYSTEM SHALL drop it
- [ ] S-041/8 WHEN `config.json` has no `breaker` command THE SYSTEM SHALL skip and log it
- [ ] S-041/9 WHEN `verify` runs after a fix round THE SYSTEM SHALL rerun the kept repros and record a pass as "fixed"
