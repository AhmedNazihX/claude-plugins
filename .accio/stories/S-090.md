## Context
After this ships: wand starts each run with `accio-board wand-reset`, which clears `.accio/run/wand/`, so seeker's,
wandmaker's and first-year's notes are always this run's; a helper reply without its `findings:` / `options:` /
`notes:` line, a missing notes file, or first-year's new `incomplete` reply is said as "the <role> didn't run: <why>"
in What happened, never as "found nothing". We'd know because `wand-reset` empties the folder, and wand's skill names
the didn't-run wording.

Why: the helpers write fixed files under `run/wand/` (curfew lists them in policy.py) and nothing clears them, so a
helper that dies leaves the last run's notes in place and wand reads them as new; and first-year (S-081) has no way to
say it couldn't read the design, so a failed read looks like "the fresh reader found nothing". The same gap S-080
closed for the code reviewers.

Design: (1) `accio-board wand-reset`: removes the files in `run/wand/` (refuses while a build runs, like other board
writes; nothing there is fine); wand step 1 runs it, and wand's `allowed-tools` lists it. (2) wand steps 3, 4 and 6.3:
check each helper's reply line and that its file exists; otherwise "the <role> didn't run: <why>" and go on without it
(first-year), or say it and stop (seeker, wandmaker: the design rests on them). (3) first-year.md: when the design
can't be read, reply `notes: none · incomplete: <path>`.
