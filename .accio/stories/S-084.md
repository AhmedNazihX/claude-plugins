## Context
After this ships: examiner, professor, auror and boggart start with `omitClaudeMd: true`, so the user's personal
rules no longer reach them; and the review package names the project's own instructions file (the main checkout's
`CLAUDE.md`, and `.claude/CLAUDE.md` when it exists) under "The project's rules", to apply where the story's change
touches them. We'd know because each of the four agent files sets it, a review package in a repo with a `CLAUDE.md`
names it, and one in a repo without has no such line.

Why: Google's Elephant-Goldfish Model runs every reviewer with `omitClaudeMd: true` and passes the review rules
explicitly. accio's reviewers load the user's global rules today ("Test coverage meets 80% minimum", "STOP and use
security-reviewer agent", a severity table), which pull a reviewer away from the story's DoD and accio's own rules.
The first build of this story (iteration 30) only set `omitClaudeMd`, and was rejected: the same setting also drops
the project's `CLAUDE.md`, which holds rules a reviewer must check and that live nowhere else. Jaza's, for example:
never write into the CLIs' config folders (`~/.claude`, `~/.codex`), never read or store a CLI's login, don't edit
`project.pbxproj` to add files, new tests use Swift Testing. The setting can't keep one and drop the other, so the
package hands the project's rules over by path.

Design: (1) `omitClaudeMd: true` in the frontmatter of examiner, professor, auror and boggart; house-elf and
headmaster keep the instructions files (house-elf writes code to the project's conventions; headmaster writes
questions for the user, which the user's question rules govern). (2) `review.py` (`_render` and `package_fix`):
a `rules_line` naming each of `CLAUDE.md` and `.claude/CLAUDE.md` that exists in the **main checkout** (not the
worktree: a story must not change the rules it is judged by), as "The project's rules: `<path>` (apply them where
the change touches them; accio's rules in your prompt come first)"; none exists → the line is left out.
`review-package.md` gets the `$rules_line`. boggart reads the same package, so it gets them too. (3) The four agents'
prompts: read the project's rules the package names. (4) Tests: the frontmatter split (four set it, house-elf and
headmaster don't), the package line present with each file and absent without, the main checkout's file named even
when the worktree's copy differs. DESIGN notes where the reviewers' rules come from.
