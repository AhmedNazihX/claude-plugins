## Context
After this ships: a story that changes the code that makes mad-eye's evidence (for Jaza, its `--ui-walk` mode and
its window capture) is not judged from screenshots that changed code made. We'd know because such a story's review
shows "mad-eye skipped: the story changes how its evidence is made (<files>); a person should look" instead of a
pass.

Why: S-068 runs `ui_evidence.command` in the story's own worktree, so the story's code builds the app that takes
the screenshots. That is needed (main's build doesn't hold the story's UI), but it means a story that edits the walk
mode or the capture can change its own evidence, on purpose or by accident (say, a capture that returns a stale
image). S-068 made mad-eye write the steps so the builder never picks its evidence; this closes the other half.
Raised 2026-10-24 by a side agent while S-068 was building. Running the walk from main's build instead was ruled
out: main's app doesn't contain the story's change, so its screenshots would show the old screen.

Design: a new optional `ui_evidence.evidence_globs` (list of globs: the files that make the evidence). When the
story's diff touches one, accio doesn't run the command and skips mad-eye with the note above; the story still
merges through its other reviews, and owl lists the note so the author looks by hand. Without `evidence_globs`,
config is refused when `ui_evidence` is set (the project must name them; an empty list is allowed and means "none").
## Definition of Done
- [ ] S-069/1 WHEN config has `ui_evidence` without `evidence_globs` THE SYSTEM SHALL refuse the config with a message naming the key
- [ ] S-069/2 WHEN a story's diff touches an `evidence_globs` file THE SYSTEM SHALL not run the evidence command and SHALL skip mad-eye with a note naming the files and saying a person should look
- [ ] S-069/3 WHEN a story's diff touches no `evidence_globs` file THE SYSTEM SHALL run the evidence step as in S-068
- [ ] S-069/4 (no test) checks pass: `python3 tests/run_tests.py`
