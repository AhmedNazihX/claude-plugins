## Context
After this ships: the user types one command (`/accio`) and accio carries the work from wherever the board stands to a pushed, CI-checked result, stopping only at real decisions. We'd know because in one real iteration the transcript has a single `/accio`, every other message from the user answers a real question, and no step ends with "type /accio:X".

This story is the by-hand spikes of design "One command: /accio", part 2 (S1 and the wake: S2, S3 or S5). It must be done before S-006, the conductor. Its results decide whether `/accio` starts the build itself or says "type /accio:brew", and whether the chat wakes by itself when the build ends or the user types `/accio` after it and it picks up at review. Each fallback costs one typed command, never a skipped safety check.

## Review notes
**S1, first try (2026-10-19 10:59).** After iteration 4 was planned, the main chat was asked to start the build with
no command from the user (the user typed only "continue"). It did not start it, and that is the rule, not a bug:
Claude Code's `Workflow` tool runs only on the user's explicit opt-in (a typed slash command whose instructions call
`Workflow`, the user's own words "run a workflow", or ultracode), and prophecy says "never start the build yourself".
A skill the model loads on its own does not count as the user's opt-in. Consequence for S-006: `/accio` can start the
build only because the user typed `/accio` and its own instructions say to start it; a bare "continue" or a skill
chained by the model cannot. S1 still needs one real try where the user's typed command is what opts in.
