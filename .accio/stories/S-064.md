## Context
After this ships: `/accio` goes from a new design note straight to sort, every flag that decides whether a review step runs comes from a script, and mad-eye can't quietly wander off the preview. We'd know because after the next wand note `accio-board next` says `sort`; `brew.js` asks portkey to compute no flag itself; a test shows an off-origin page after a click is hidden from mad-eye and fenced; auror's checklist has the two-parsers line; and the next story that adds an agent lists `accio/README.md` in its `files`.

Why this story: requirement L5 of "Group B leftovers", second half. Once the fence hook (S-063) writes a fence record, curfew must stop mad-eye from clicking around on a page that is off the preview.

Design: while a fence record exists for the `agent_id`, curfew allows mad-eye only `browser_navigate` (still checked against the origin) and `browser_close`, and denies its read tools: the Playwright server also saves the off-origin page under `.playwright-mcp/`, which mad-eye could otherwise read (spike S-L5, finding 4). The fence lifts when a response shows the preview's origin again (S-063 removes the record). If the record is missing, today's rules apply; if it exists but can't be read, mad-eye counts as fenced (push security review). The lists stay exact (decision 010).

Fence record, as S-063 writes it: the JSON file `.accio/run/mad-eye-fence.json`, a map `{"<agent_id>": {"url": "..."}}`. The agent is fenced when its `agent_id` is a key. Use the same file-name constant S-063 defines.
## Reuse
The mad-eye allow-list and navigate-origin rule in `accio/bin/accio_lib/policy.py` and `accio/hooks/curfew.py`; `_read_json` in curfew; the fence file written by `accio/hooks/fence.py`.
