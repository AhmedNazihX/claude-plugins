## Context
After this ships:
- house-elf's brief lists the config's `agent_allow` commands under the commands it may run, and house-elf.md names
  the same read and file commands curfew allows (from `bashpolicy`), so a builder never skips a command it is allowed.
- `accio-board record-design` commits `.accio/config.json` whenever it has changes (not only while git doesn't track
  it), so check commands added by a later design note are committed with it.
- wand keeps every check command checkfinder proposes and says so in one line (the user can remove one later),
  instead of stopping before the interview; and it asks first-year's small points as one "I'll assume A, B and C" line,
  asking only real decisions one at a time.
We'd know because a brief in a repo with `agent_allow` names those commands, record-design commits a changed
config.json, and wand's skill has no stop before the interview.

Why: S-081's builder wrote "I could not run `claude plugin details`" although it is in this repo's `agent_allow`; the
brief template lists only `accio-claim` and `accio-board refresh` under "Scripts you may run", and house-elf.md's list
is narrower than `bashpolicy`'s (`head`, `grep`, `find`, `cp`, `mv`, `rm`, `git show/restore/mv/rm`). `design.py`
`_setup_files` adds config.json only when git doesn't track it yet, so later check edits stay uncommitted without a
word. wand step 1 asks which check commands to keep, a low-stakes choice the user has asked not to be stopped for;
and first-year can return up to 10 points, each asked alone.

Design: (1) brief.py: the template's command section adds each `agent_allow` command (exact, as curfew matches it);
house-elf.md lists the commands from `bashpolicy` and says "and those your brief lists". A test reads bashpolicy's
list and house-elf.md so they can't drift. (2) design.py `_setup_files`: config.json when `git status --porcelain`
shows it changed or untracked. (3) wand step 1: keep all proposed checks, say "I kept these check commands: …;
say if one should go"; step 6.3: small points (wording, a default with an obvious answer) in one assumption line,
written into the design, then each real decision alone.
