## Context
After this ships: a build in a new or freshly set-up repo can't silently skip its tests, a rebuilt story never hands back its old unreviewed work as done, and a direct fix to accio gets accio's own reviewers. We'd know because the next iteration has no stop caused by any of these three, and a direct fix's review comes from `accio-brief --review` instead of a hand-written package. This story is part 5 of "Lessons from iteration 1" (R5): brew honours `wip` from `config.json` (DESIGN § 5.2); today `workflows/brew.js` fixes it at 3, so iteration 2 set `wip: 1` and still built 3 at once.

The shape changes. Today `accio-board ready --json` prints a bare JSON array of story items (`cmd_ready` in `accio/bin/accio-board`). After this story it prints an object: `{"wip": <int>, "stories": [<the same items as today, in the same order>]}`. The plain (non-`--json`) output is unchanged. Every reader of the array moves to `stories`: the portkey agent, the load step in `brew.js`, and the tests that call `ready --json` (`accio/tests/test_board.py` lines 51, 242, 260; `accio/tests/test_plan.py` line 253).
## Reuse
`accio/bin/accio_lib/config.py` already defaults `wip` to 3 and validates it as a positive integer. `cmd_ready` in `accio/bin/accio-board` is the load step; `brew.js` caps running stories at `WIP` (line 26, used near line 340). The load step is a portkey agent that runs `accio-board ready --json --resume` and replies in `LOAD_SCHEMA` (`brew.js` lines 52-54, 385-391); `accio/agents/portkey.md` (line 13) describes that reply.
