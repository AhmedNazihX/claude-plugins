## Context
After this ships: when examiner, professor or auror can't read its review package, the diff, the story or a checklist
the package names, it replies `"verdict": "incomplete"` with what it couldn't read, and brew blocks the story with
one plain question instead of counting a pass or starting a fix round; boggart says the same, and brew keeps it as a
note; sort's backlog check that comes back incomplete is said in sort's summary, never taken as a pass. We'd know
because a stub reviewer that replies incomplete ends the build with that story BLOCKED and a question naming the
reviewer and the file.

Why: Google's Elephant-Goldfish Model gives every reviewer this rule: "If a required file cannot be read, report an
incomplete review instead of a verdict." accio's reviewers can only say `pass` or `fail` (`REVIEW_SCHEMA` in
`brew.js`), so one that read nothing can reply `pass` with zero findings and the story goes on. It is the same fail-open
gap S-076 closed for boggart's verify: a step that didn't run looked like a step that passed.

Design: (1) `REVIEW_SCHEMA`'s verdict takes `incomplete`, with a `missing` string. (2) In `reviewLoop`, any
`incomplete` reply stops the story with `accioStop` (accio's own failure, not the code's): "The <role> (<name>)
couldn't read <missing>, so it gave no verdict. Fix that and review again?" No fix round runs: house-elf can't fix
an unreadable package. (3) examiner, professor and auror's prompts: read the package, the diff, the story and every
checklist it names before any verdict; if one can't be read, write no findings and reply incomplete with its path,
counts all 0. (4) boggart's reply can carry `incomplete` with `missing`; brew keeps it as a note
("boggart couldn't read …"), as S-076/2 does for a try with no answer. (5) sort step 4: an incomplete backlog check
is called once more; if still incomplete, sort goes on and names it in the summary and the "What I need" line.
## Definition of Done
- [ ] S-080/1 WHEN examiner, professor or auror replies `incomplete` THE SYSTEM SHALL block the story with one question naming the reviewer and what it couldn't read, and run no fix round
- [ ] S-080/2 WHEN every reviewer replies pass or fail THE SYSTEM SHALL review and fix as before
- [ ] S-080/3 WHEN boggart replies `incomplete` THE SYSTEM SHALL keep the story going with a note naming what it couldn't read
- [ ] S-080/4 WHEN examiner's, professor's, auror's or boggart's prompt is read THE SYSTEM SHALL tell it to reply incomplete, with the path, when a file it needs can't be read
- [ ] S-080/5 WHEN sort's backlog check comes back incomplete twice THE SYSTEM SHALL say so in sort's summary instead of treating it as a pass
- [ ] S-080/6 (no test) checks pass: `python3 tests/run_tests.py` and `node --test 'tests/workflow/**/*.test.mjs'`
