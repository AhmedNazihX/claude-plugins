## Context
After this ships: a build stops for the user only for a real decision, and every finding, block and break leaves a reason. We'd know because over the next two iterations no story blocks with "Should it be fixed and built again?" or on a one-off accio hiccup; each `.accio/iterations/<N>.md` has one line per finding and block saying how it ended; every boggart break that reached a fix round came with a repro that failed twice on head; owl reports a cost for every build; and the guard and allow-list tests pass.

Why this story: boggart's eval set, run by hand on 2026-10-20 (Claude Code 2.1.304, accio from main at `6a35540`), caught all 3 planted breaks with no false break on the 3 clean stories. But `accio-break` kept only 1 of them. `judge` in `breaker.py` calls any repro that also fails on base "pre-existing" (`fails on base too: out of scope`). When the story adds a file, or a name in an existing file, base doesn't have it, so the repro fails there with an import error. So a break in new code can never be kept. That was the case for 2 of the 3 planted breaks (break-empty-list and break-last-page), and boggart asked about it in both replies.

The fix: on base, only a failure for the same reason counts as pre-existing. A base run that fails with a setup error (`SETUP_ERROR`: ImportError, ModuleNotFoundError, …) means the code under test isn't on base, so the break is the story's own and is kept.

Also: since S-052, curfew lets boggart write only under `run/<ID>/boggart/repros/`, but `agents/boggart.md` still says "Repros go only in `run/<ID>/boggart/`".
## Reuse
`judge`, `_run_at`, `_kind` and `SETUP_ERROR` in `accio/bin/accio_lib/breaker.py`; the base and head repo fixtures in `accio/tests/test_breaker.py`.
