## Context
After this ships: a guard that can't start never blocks a tool call outside accio's build agents, while an accio agent still gets a deny when curfew crashes at start-up. We'd know because a test runs curfew with its library made unimportable and sees a deny for an `accio:*` caller and a silent exit 0 for anyone else, and `hooks/hooks.json` has no `onFailure`.

Why: S-028 gave protego, fidelius and curfew `"onFailure": "block"`. Those guards run in every session and project, so one start-up crash (a broken update that makes `from accio_lib import ...` fail) would block every tool call everywhere. This comes from the design note "Guards fail open (decision 007)" and ships as 0.6.1. Out of scope: a missing `python3` or a guard past its time limit (the call goes through), and protego and fidelius start-up crashes (they fail open).
## Reuse
`_answer` in `accio/hooks/curfew.py` (use the same JSON shape for the deny). The existing S-028 test in `accio/tests/test_scaffold.py`, which changes to expect no `onFailure`.
