## Context
After this ships: a build stops for the user only for a real decision, and every finding, block and break leaves a reason. We'd know because over the next two iterations no story blocks with "Should it be fixed and built again?" or on a one-off accio hiccup; each `.accio/iterations/<N>.md` has one line per finding and block saying how it ended; every boggart break that reached a fix round came with a repro that failed twice on head; owl reports a cost for every build; and the guard and allow-list tests pass.

Why this story: running the eval set by hand on 2026-10-20 hit four snags, each worked around by hand:
1. The `change.diff` files have wrong hunk line counts (for example `@@ -0,0 +1,9 @@` over 4 lines), so `git apply` fails.
2. The README says to run boggart with the Task tool or `claude --agent accio:boggart`. An installed accio before S-052 lets boggart do nothing under curfew, and curfew sees the agent as `accio:boggart` only when it runs as a plugin agent. What worked: `claude -p --plugin-dir <a copy of accio from main>` with a Workflow `agent()` of type `accio:boggart`, the prompt on stdin (a `--allowedTools` list swallows a prompt given after it).
3. The README doesn't say the scratch repo needs `.accio/config.json` with a `breaker` command and `checks` entries that each have a `glob`.
4. The `story.md` files have no accio frontmatter, so `story.parse` fails on them.
The harness used is in the session scratchpad (`boggart-eval/setup.py`, `run_case.sh`); the story may write its own.
## Reuse
The six cases in `accio/evals/boggart/`; `accio/bin/accio_lib/config.py` for the `breaker` and `checks` shapes; `accio/bin/accio_lib/story.py` for the frontmatter.
