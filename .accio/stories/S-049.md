## Context
After this ships: a build stops for the user only for a real decision, and every finding, block and break leaves a reason. We'd know because over the next two iterations no story blocks with "Should it be fixed and built again?" or on a one-off accio hiccup; each `.accio/iterations/<N>.md` has one line per finding and block saying how it ended; every boggart break that reached a fix round came with a repro that failed twice on head; owl reports a cost for every build; and the guard and allow-list tests pass.

Why this story: R8 and R9 of "Group B: fewer stops, a reason for every ending" (decision 008), second part. The preview runs the user's app and handles test login details. accio can't check the data is test data: `test_data` is the user's word. Login details come only from environment variables named in `preview.login`.

The spike (`accio/docs/research/spike-s-m2-m3.md`, finding 2) found that the Playwright MCP server writes page and console logs to `.playwright-mcp/` at the repo root on every browser session. The main-checkout snapshot must skip that folder, or a mad-eye story blocks as `main_changed` on its own logs.
## Reuse
`accio/bin/accio_lib/preview.py` and `config.py` from S-045.
## Definition of Done
- [ ] S-049/1 WHEN `preview` lacks `"test_data": true` THE SYSTEM SHALL refuse to start and name the missing field
- [ ] S-049/2 WHEN `preview.login` names an environment variable that is unset THE SYSTEM SHALL refuse to start
- [ ] S-049/3 WHEN `preview.login` is set and both variables are present THE SYSTEM SHALL write `run/<ID>/preview-login.json`, git-ignored, with the values of those variables
- [ ] S-049/4 WHEN `config.json` holds a password or username value in `preview.login` THE SYSTEM SHALL refuse to start and write no `preview-login.json`
- [ ] S-049/5 WHEN `preview.env` is set THE SYSTEM SHALL pass those variables to the preview process
- [ ] S-049/6 (no test) checks pass: `python3 tests/run_tests.py`
- [ ] S-049/7 WHEN the build compares the main checkout before and after a story THE SYSTEM SHALL skip a `.playwright-mcp/` folder at the repo root (the Playwright MCP server writes its page and console logs there on every browser session; spike finding 2), so a mad-eye story never blocks as main_changed on those logs
