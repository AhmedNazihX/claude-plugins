## Context
After this ships: the user can use accio as their everyday coding workflow and finds it adds value, and we'd know because they use it themselves and learn from what goes wrong. For howler: after owl pushes, without being asked, a short report appears in the chat within a few minutes of CI ending. It gives PASSED or FAILED for each workflow and job; for a failure, the failing step or test and its error, `real` or `first failure`, and whether the cause lies inside the pushed range. We'd know by running one real iteration in this repo (howler itself), pushing, and seeing the report arrive while the user does something else.

This story is part 1 of the design (curfew's list for howler, R2 and R5). It lets howler run exactly its 7 git and gh commands plus `tail`, with every argument checked (decisions 001 and 002), and nothing else.

The fixed lists (the builder must use these, no others):
- Flags per command: `gh run list`: `--commit`, `--workflow`, `--branch`, `--limit`, `--json`. `gh run view`: `--json`, `--log-failed`, `--job`. `gh run watch`: `--exit-status`, `--compact`. `git diff`: `--name-only`. `git merge-base`: `--is-ancestor`. `tail`: `-60`. `git rev-parse` and `git remote get-url` take no flag.
- JSON fields (after `--json`, comma-separated): `databaseId`, `workflowDatabaseId`, `headSha`, `headBranch`, `status`, `conclusion`, `name`, `jobs`.
- Value patterns: `^\d+$` (ids and `--limit`), `^[0-9a-f]{40}$` (a sha), `^[A-Za-z0-9._/-]+$` (a branch, and `git rev-parse` / `git remote get-url` words such as `HEAD`, `origin`).
- Redirect allowed only as `> /dev/null 2>&1` after `gh run watch`; pipe allowed only into `tail -60`.
## Reuse
`AGENTS` and `_other_judge` in `accio/bin/accio_lib/policy.py` (today it indexes `SCRIPTS[kind]`; howler needs its own branch). `Judge` in `bashpolicy.py` (its prefixes have no argument check today, only accio scripts do). Existing rows in `accio/tests/test_curfew.py`.
