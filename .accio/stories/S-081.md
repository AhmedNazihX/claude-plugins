## Context
After this ships: before wand records a design or a design note, a new agent, `first-year` (the fresh reader), reads
only the written design, the code and `.accio/decisions/`, with no memory of the interview, and lists what a builder
would have to guess, what nobody needs yet, existing code that already does the job, and any clash with a recorded
decision; wand turns what it finds into questions while the user is still in the session. Separately, when a design
note contradicts a recorded decision, wand asks whether to replace that decision or change the note. We'd know
because a design with an undefined term or a clash with a decision gets a question before `record-design`, and the
`first-year` agent's notes file is written for every design run.

Why: Google's Elephant-Goldfish Model (github.com/google/elephant-goldfish-model, read 2026-10-25) has a "naive
reader" and a "zoom-out" reviewer read the spec with zero context, because the session that wrote it can't see its
own unstated assumptions. In accio nobody with fresh eyes reads `design.md` before sort; quill finds some gaps later
(`question:` replies), when asking the user costs more. EGM's "contradiction auditing" rule is the clash check.

Design: (1) `accio/agents/first-year.md`: model sonnet, `omitClaudeMd: true`, tools Read, Grep, Glob, Write, maxTurns
40; writes only `.accio/run/wand/first-year-notes.md` (curfew: `"first-year": Lists(writes=("run/wand/first-year-notes.md",))`).
Its prompt: read the design (or the named note section), the code it names and `.accio/decisions/`; nothing else
from the session is given. List, each with the design line: a term or step a builder would have to guess; a part
nobody in the design needs (no owner, or speculative); existing code that already does a part (search for it, give
`file:line`); a clash with a recorded decision (its number). At most 10 points, most important first; "nothing found"
is a fine answer. Reply one line: `notes: <path> · points: <n>`. Add its row to `accio/README.md`'s agent table.
(2) wand step 6: after writing the design or note and before `accio-board record-design`, call `accio:first-year`
once with only the design path (and the note's heading for a note). Read its notes; drop a point the interview
already settled; ask each remaining one as a question in the interview format, one at a time; write each answer
into the design with Edit; then record. One read-back only: never call it twice in a run. With `driven`, these
questions are still asked (they are real decisions); with no points, go on and say "the fresh reader found
nothing" in the What happened line. (3) `interview.md` and wand step 2: read the titles of `.accio/decisions/*.md`
(and any that bear on the idea); when the new design or note contradicts one, say which and ask: replace the decision
(record a new one with vow whose text says "Replaces decision NNN"), or change the note. (4) A wand eval case for
each: a design with an undefined term gets a question; a note that contradicts a decision gets the clash question.
