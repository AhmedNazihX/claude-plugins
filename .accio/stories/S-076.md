## Context
After this ships: when boggart has found breaks but their verify step can't run, the story is Blocked with one plain
question instead of READY; every "skipped", "did not run" or "gave no answer" note from boggart or mad-eye shows in
the owl review under the story's Risks; and a test proves every command and write `brew.js` gives an agent is allowed
by the real curfew hook. We'd know because a build whose verify fails ends with S-0xx BLOCKED and that question.

Why: on 2026-10-24 S-075's build ended "READY · boggart's verify gave no answer" although boggart had found a real
break in a DoD line. `brew.js` (`boggartStage`, `if (!verified(reply)) return {... note: "boggart's verify gave no
answer"}`) treats a verify that fails the same as a clean one: the story goes on with a note. Curfew had denied prefect
`accio-break <ID> verify` since 0.8.0 (fixed directly in `f8985df`), so every break boggart found in a real build was
dropped this way; a re-run of the 13 saved repros found 2 still real (S-060/4, S-068/5, fixed by S-077). Nothing
showed it: tests use stub agents with no curfew, and the note only appears in brew's end table, not in `owl.md`, which
`accio-summary` builds from build reports and never sees the notes. The same blind spot hid S-070's and S-071's
curfew gaps (prefect couldn't run `accio-preview` or write findings files).

Design: (1) In `boggartStage`, when `tried.breaks` is non-empty and verify fails (also after the repair turn), `stop`
with a question naming the breaks' DoD ids, the verify error, and the two ways on (fix the error and rebuild, or
answer to accept without fixing). A failed boggart *try* (no breaks reported) stays a note: nothing was found to drop.
(2) brew's notes reach the review: store each story's note where `accio-summary` can read it (for example in the
outcome step prefect already runs, or a `run/<ID>/notes.md` prefect writes; if that is a new curfew write or argument,
add it narrowly and test it through the hook), and `owl.md` lists it first under that story's Risks. (3) A curfew
contract test: for each `agentType` call in `brew.js`, the commands and writes its prompt tells the agent to run
(`accio-check`, `accio-preview` forms, `accio-break <ID> verify`, `accio-board move/refresh`, `accio-ledger …`, the
findings and steps files, …) go through the real hook as that agent and are allowed. Read them from `brew.js`'s
prompts, or keep one list next to the test that a check compares with `brew.js`, so a new prompt can't skip it.
