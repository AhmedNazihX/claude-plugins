## Context
After this ships: a story whose `risk` names a guard (`curfew`, `guard`, `hook`, `sandbox`, `access`) gets auror and
the security checklist, as `auth` or `secret` already do; brew's package reply must carry `risky`, so a reply that
drops it is retried and never read as "not risky"; and portkey's prompt lists every package field brew needs. We'd
know because a story with `risk: curfew …` gets an auror review, and a stub package reply without `risky` is retried.

Why: in October no story that changed curfew got a security review. S-069, S-071, S-079 and S-082 all name curfew in
their `risk` field, but `review.py`'s security words are only auth, security, secret, permission and payment
(`CHECKLIST_WORDS`), and this repo set no `risky_paths`. Every curfew gap that day was found after merge by an
outside security review (`155e754`, `88d71ab`, `bf12b48`, the S-082 run-folder gap). Separately, `PACKAGE_SCHEMA`
requires `code, breaker, ui, preview, test_data` but not `risky` (brew.js), so a Haiku reply without it makes
`panel()` skip auror silently: the gap S-058 and S-061 closed for the other flags. portkey.md's step 4 still lists
only `{package, diff, head, risky}`.
(This repo's own `.accio/config.json` now lists accio's guard files in `risky_paths`, set by hand on 2026-10-25.)

Design: (1) `review.py`: add `curfew`, `guard`, `guards`, `hook`, `hooks`, `sandbox`, `access` to the security words
(whole words, as now). (2) brew.js `PACKAGE_SCHEMA.required` gains `risky`. (3) portkey.md step 4: the reply is the
script's JSON as it is, naming every field (`package, diff, head, risky, code, breaker, ui, preview, test_data`).
(4) Tests: a story with `risk: curfew (…)` is risky and gets the security checklist; `risk: ui` isn't; a stub package
reply without `risky` is retried and the story still gets auror once it comes; portkey.md names every
`PACKAGE_SCHEMA` field (a test reads both, so they can't drift).
