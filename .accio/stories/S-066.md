## Context
After this ships: a page that leaves the preview on a timer can't reach mad-eye through a screenshot or the console either. We'd know because a fence test hides a screenshot response that carries no on-origin `Page URL`, and a live walk still saves one screenshot per DoD line.

Why this story: the push security review of `2b33404` (raised three times). The fence learns where the browser is only from responses that carry a `### Page` section. A preview page that redirects away later, on a timer, is not fenced until the next such response; a `browser_take_screenshot` or `browser_console_messages` before that passes as it is (S-065, known limits).

Design: for `accio:mad-eye`, a browser response that has no `Page URL` line on the preview's origin is treated as unverified. A screenshot response is replaced with one text block saying the screenshot was saved to the `filename` it was given and the picture is hidden; the file is still written, so the user's evidence stays. Any other unverified response with page content (console messages) is replaced with the fence's reason. `browser_close` passes. mad-eye's prompt says it checks a DoD line with `browser_snapshot`, and takes the screenshot only as evidence for the user. First check live which browser tools' responses carry a `### Page` section, and record it in `accio/docs/research/spike-s-l5.md`.

Defaults (prophecy, iteration 22): the builder can't run a live browser, so S-066/6 is done by hand after the merge, and the hook must not depend on its answer. Only `browser_take_screenshot` and `browser_console_messages` are treated as unverified when they have no on-origin `Page URL`; any other tool's response without a `### Page` section passes as today (it holds the tool's own result, not page content), and a response with a `### Page` section follows the existing rules. When mad-eye is not fenced, the replacement text doesn't say the page is off the origin: it says the response can't be shown because it doesn't show the page is on the preview, and to check with `browser_snapshot`.
